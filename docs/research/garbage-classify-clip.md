## TL;DR

- **路线**：用开放词汇 CLIP 类零样本。词表物品名离线算成文本向量内置，设备上只跑图像塔，图片向量与词表向量做余弦相似度取 top-3，再查垃圾四分类。云 API 和专训模型都不推荐。
- **模型**：SigLIP2 base/16 + 英文词表最好，图像塔用 q4f16（约 55MB，按需下载）。TinyCLIP-8M 不可用，TinyCLIP-39M 勉强，Chinese-CLIP 不如 SigLIP2。SigLIP2 的 int8 版精度崩，不能用。
- **展示**：top-3 物品让用户点选，默认分类取按类别聚合概率最大的一类，聚合置信度低于约 0.8 时提示“拿不准，请选择”。
- **中文**：匹配用英文名向量，界面显示词表里对应的中文名。设备上不需要文本塔。
- **局限**：测试图偏干净、分类标注是草稿、没在手机上测。q4f16 在手机 ORT 上能否运行，见下方“待验证”。

## 1. 问题与约束

- 目标：拍照或选图，识别垃圾物品并给出分类（上海标准：可回收物 / 有害垃圾 / 湿垃圾 / 干垃圾）。
- 约束：体积小、离线优先，模型按需下载、不进 APK；推理走共享 ONNX Runtime（见 [spike-ort-sherpa](spike-ort-sherpa.md)）；新增依赖要先问用户。

## 2. 路线对比

| 路线 | 结论 |
|---|---|
| 云 API | 只确认阿里云有 `ClassifyingRubbish`（返回物品名和干湿四类）。要联网、AccessKey 不能放 App、要自建代理，和“联网只走原生、离线优先”冲突；单价与免费额度没查到。百度、腾讯无专用接口，华为图像识别 2026-06-30 停售。不推荐。 |
| 端侧专训模型 | 没有授权清楚的中国四分类数据集和现成模型。华为云杯数据集约 44 类（授权未查到）、TrashNet 只有 6 类、TACO 偏国外、餐厨 27 类检测集授权为空。不推荐。 |
| 通用分类 + 词表 | ImageNet 1000 类覆盖不足（外卖盒、纸巾、药片等不在其中）。ML Kit 标签约 400 个且依赖 Play 服务。不推荐。 |
| **开放词汇 CLIP 零样本** | 词表可随意增删，不受固定类别限制。采用。 |

词表来源：没有合规开源的“物品名→四分类”数据。可参考上海《生活垃圾分类投放指引（2024 版）》自行整理，政府文件的引用方式需另行确认；各城市叫法不同（上海干/湿垃圾，其他城市其他/厨余）。

## 3. 候选模型（体积来自 HuggingFace 文件列表，估算已标注）

| 模型 | 图像塔体积 | 许可证 | 结论 |
|---|---|---|---|
| TinyCLIP 8M/16 | fp32 33MB，q4f16 5MB（拆子图实测） | 卡片标 MIT，训练数据 YFCC15M 衍生风险待评估 | 精度不够 |
| TinyCLIP 39M/16 | fp32 155MB，q4f16 23MB | MIT（卡片） | 勉强 |
| SigLIP2 base/16 | fp32 372MB，int8 95MB，q4f16 55MB | Apache-2.0 | 选用 |
| Chinese-CLIP | 官方只有 753MB 整包，图像塔约 345MB（估算） | MIT | 不如 SigLIP2 |
| MobileCLIP2-S0 | 约 12MB | apple-amlr，只许非商业研究 | 不能用 |
| RAM++ / OWL-ViT / YOLO-World | RAM++ int8 约 873MB；OWL-ViT int8 约 155MB；YOLO-World 为 GPL/AGPL | — | 排除 |

TinyCLIP 官方是图文联合 onnx，图像塔要用 `onnx.utils.extract_model` 拆出。SigLIP2 的 `vision_model*.onnx` 是官方单独文件。

## 4. 四模型对比测试

### 4.1 方法

- **词表**：约 150–300 条日常垃圾物品，含中文名、英文名、上海四分类。分类标注为草稿，**需对照官方指引核对**。重点覆盖易混对：纸盒/油污外卖盒、各类电池、药品、纸巾/纸张、塑料瓶/奶茶杯、果皮/骨头、陶瓷/玻璃、烟蒂/灯管、衣物。
- **测试图**：共 301 张，只在本机使用，不进仓库。
  - Wikimedia Commons：抓取 353 张，拼图肉眼核验后剩 201 张，覆盖 125 个物品，授权为 CC BY / CC BY-SA / CC0 / 公有领域。
  - TrashNet 缩小版：100 张，来自 HF 数据集 `garythung/trashnet`，仓库声明 MIT；只有大类标签，物品命中按“可接受物品集合”判。
- **口径**：fp32，三个提示词模板取平均；“任一命中”指 top-3 里有一个物品的分类等于真值；“按类别聚合”指把 softmax 概率按分类求和后取最大（温度 100）。
- 延迟为 PC 上图像塔单张、batch=1、4 线程的中位数，**不等于手机**。

### 4.2 结果（Commons 201 张子集）

| 模型（词表语言） | 物品 top-1 | 物品 top-3 | 四分类 top-1 | top-3 投票 | top-3 任一命中 | 按类别聚合 | TrashNet 四分类 top-1 |
|---|---|---|---|---|---|---|---|
| TinyCLIP-8M（英） | 0.343 | 0.562 | 0.682 | 0.687 | 0.895 | 0.711 | 0.36 |
| TinyCLIP-39M（英） | 0.622 | 0.841 | 0.846 | 0.821 | 0.965 | 0.856 | 0.69 |
| **SigLIP2（英）** | **0.861** | **0.995** | **0.940** | 0.871 | 1.000 | **0.940** | 0.80 |
| SigLIP2（中） | 0.736 | 0.930 | 0.910 | 0.846 | 0.980 | 0.915 | 0.76 |
| Chinese-CLIP（中） | 0.702 | 0.910 | 0.861 | 0.841 | 0.970 | 0.871 | 0.72 |

- top-3 投票口径明显劣于 top-1 和聚合，不建议用。
- 物品 top-1 偏低，部分原因是词表有近义条目（塑料瓶/矿泉水瓶/饮料瓶），词表需合并同义项。

### 4.3 体积与延迟（PC，ms）

| 模型 | fp32 | int8 | q4f16 | PC 延迟 fp32 / int8 / q4f16 |
|---|---|---|---|---|
| TinyCLIP-8M | 33.3MB | 9.0MB | 5.3MB | 14 / 12 / 14 |
| TinyCLIP-39M | 154.6MB | 39.8MB | 22.8MB | 59 / 41 / 64 |
| SigLIP2 | 371.8MB | 94.6MB | 54.6MB | 165 / 98 / 130 |
| Chinese-CLIP | 约 345MB（估算） | 未验证 | 未验证 | 142（torch fp32） |

x86 上 q4f16 没有加速，手机上是否更快未验证。

### 4.4 量化精度损失（英文词表，三模板平均）

| 模型 | 变体 | 四分类 top-1 | 物品 top-3 | 与 fp32 top-1 一致率 |
|---|---|---|---|---|
| TinyCLIP-8M | int8 / q4f16 | 0.682 / 0.662 | 0.547 / 0.492 | 86% / 70% |
| TinyCLIP-39M | int8 / q4f16 | 0.836 / 0.841 | 0.826 / 0.836 | 86% / 79% |
| SigLIP2 | int8 | 0.806（掉 13 个点） | 0.751（掉 24 个点） | 52% |
| SigLIP2 | q4f16 | 0.965（略升） | 0.990 | 91% |

SigLIP2 int8 与 fp32 的向量余弦均值只有 0.77，q4f16 为 0.96。**SigLIP2 要么 fp32，要么 q4f16，不要 int8。**

### 4.5 提示词与对比描述

- SigLIP2：裸词最好（中文 item_top1 0.776 对“一张{}的照片”的 0.607；英文裸词 0.866）。TinyCLIP 和 Chinese-CLIP 模板间差距小。
- 给 33 个易混物品写带属性的对比描述（如“沾满油污的外卖盒”）效果不稳，易混子集物品 top-3 命中：

| 模型 | 基线 | 加描述后 |
|---|---|---|
| TinyCLIP-8M | 0.50 | 0.61 |
| TinyCLIP-39M | 0.73 | 0.82 |
| SigLIP2 中文 | 0.875 | 0.911 |
| SigLIP2 英文 | 0.982 | 0.893（变差） |
| Chinese-CLIP | 0.857 | 0.821 |

小模型有帮助，强模型不要加。

### 4.6 易混物品（样本很少，易混子集共 56 张，每组 4–9 张，只看趋势）

SigLIP2 英文，物品 top-1 / 物品 top-3 / 分类 top-1：

| 组 | n | 结果 |
|---|---|---|
| 纸盒 vs 油污盒 | 9 | 0.44 / 0.89 / 0.67 |
| 电池 | 8 | 0.62 / 1.00 / 1.00 |
| 药品 | 7 | 0.71 / 1.00 / 1.00 |
| 纸巾 vs 纸张 | 7 | 0.71 / 1.00 / 0.71 |
| 塑料瓶 vs 杯 | 8 | 0.75 / 1.00 / 1.00 |
| 果皮骨头 | 4 | 1.00 / 1.00 / 1.00 |
| 陶瓷玻璃 | 4 | 0.50 / 1.00 / 0.75 |
| 烟蒂灯管 | 4 | 0.75 / 1.00 / 0.75 |
| 衣物 | 5 | 1.00 / 1.00 / 1.00 |

易混整体：物品 top-1 0.70、top-3 0.98、四分类 0.875。最弱环节是纸盒/油污盒、纸巾/纸张（跨“可回收/干”）；有害垃圾几乎不错。

## 5. 策略

1. **展示 top-3，默认分类取聚合概率最大的类。** top-3 物品命中 99.5%，让用户点选最稳妥。
2. **“拿不准”阈值**：用分类聚合置信度（温度 100）。SigLIP2 英文下，阈值 0.82 约丢弃 25% 样本，保留部分四分类准确率 97.8%、被丢弃部分 64%；阈值 0.63 约丢弃 10%，被丢弃部分仅 30%。建议低于约 0.8 时提示并突出 top-3。**阈值只来自本测试集，上线前要用真实相册数据重标定。**
3. **易混对不靠加描述词。** 对强模型会变差。已知易混对（如纸盒/油污盒）在界面加一句人工提示。
4. **词表直接用英文裸词。**

## 6. 中文处理

- 词表每条含中文名与英文名。离线算向量用**英文名**（SigLIP2 英文明显优于中文，item_top1 0.861 对 0.736）。
- 设备上只跑图像塔，匹配结果是词表条目编号，界面直接显示该条目的中文名与四分类，用户看不到英文。
- 所以中文问题变成词表质量问题：英文名要翻译准，同义条目要合并。
- 中英向量取平均是否更稳，**待验证**（真机验证子代理里有低成本 PC 实验）。

## 7. 局限

- 测试图多为摆拍或展示图，比用户真实拍摄的垃圾照干净，实际准确率大概率更低；Commons 图标签是检索词，剔除 152 张明显误标后仍可能有少量噪声。
- 分类标注是草稿，拿不准的有：普通干电池（按有害标）、充电宝、LED 灯泡、镜子、木板、塑料袋、纸杯、铝箔纸、化妆品、奶茶空杯（标可回收）、大骨头（标干垃圾）。**需对照官方指引核对。**
- 易混子集样本很少。
- 没做 Chinese-CLIP 的 int8 与 RN50 对照、手机真机延迟；未使用 TACO（Flickr 连不上）。
- 许可证细节：TinyCLIP 的 GitHub 页面没写清代码与权重各自的授权，上线前核对仓库 LICENSE；YFCC15M 训练数据衍生风险待评估。

## 8. 待验证与下一步

- **q4f16 在手机 ORT 上能否运行**（MatMulNBits 算子、full 与 mobile 包差异）、延迟、内存、与 PC 向量一致性：已派真机验证，结果出来后补充到本文档。
- 项目已有 sherpa 自带 ORT 1.28.2（见 [spike-ort-sherpa](spike-ort-sherpa.md)），是否带该算子要在验证中确认；集成若需新增依赖，先问用户。
- 与 [media-ai.md](../design/tools/media-ai.md) 的“图像识别”设计冲突：原设计是 ImageNet 1000 类，改为 CLIP 零样本后需同步更新。
