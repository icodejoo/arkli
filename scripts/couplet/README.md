# 对联分类与横批推导

把对联训练集（上联/下联）推导成“分类 + 权重 + 横批”的启发式工具。结果是**推导值，不是真实横批或人工标注**，只适合做 App 的粗筛与默认排除，不能当事实用。

## 怎么跑

```powershell
# 1) 单测（标准库，不依赖第三方）
python -I scripts/couplet/test_derive.py

# 2) 挖掘词典 mined 字段（约 40 秒；只改 lexicon.json 的 mined，不动人工 seeds/blacklist）
python -I scripts/couplet/build_lexicon.py --min-count 10 --top 40

# 3) 小批试跑（输出到临时目录，不要覆盖正式产物）
python -I scripts/couplet/derive.py --limit 20000 --out <临时目录>

# 4) 全量（约 90 秒，输出 derived.tsv 约 63MB + stats.json）
python -I scripts/couplet/derive.py
```

默认数据目录 `E:\workspaces\arkli-models\_src\couplet-clean\x\couplets\train`，默认输出 `E:\workspaces\arkli-models\_src\couplet-derived\`。

## 文件

| 文件 | 作用 |
| --- | --- |
| `derive.py` | 读数据、去重、打分分类、挑横批、写输出与 stats |
| `build_lexicon.py` | 用种子词伪标注，统计特异性词，写回 `lexicon.json` 的 `mined` |
| `lexicon.json` | 16 类定义、人工种子词 `seeds`、挖掘词 `mined`、黑名单、阈值与挽联否决规则 |
| `banners.json` | 各类横批库，2~7 字，四字为主 |
| `test_derive.py` | 单测：打分、阈值、否决、字数规则、横批选择、确定性、真实资源约束 |

## 方法

**1. 去重与清洗。** 去掉所有空白，按 `上联+下联` 的 blake2b 摘要去重（只存 16 字节摘要，省内存）。训练集 741,095 行，去重后 **736,214 对**；按上联去重为 **568,021**。

**2. 词典打分分类。**
- 词典词按字数 1~max 逐位置匹配，同一词只计一次。
- 每类得分 `w = 1 - exp(-Σ命中词权重)`，低于阈值 0.35 丢弃。
- 命中挽联强词（权重 ≥ 0.7）时否决：去掉除 挽联/人生/山水/文墨 外的所有类，挽联权重至少 0.8。
- 最多保留 3 类，按权重降序；一个都不剩则归入通用（权重 0.5）。

**3. 词典怎么来的。** 人工种子词（每类约 15~45 个，带权重）→ 用种子对去重对联做伪标注（某类种子得分领先且领先 ≥0.5 才标注，约 16% 的对联被标注）→ 统计 2~4 字子串在各伪标注类中的次数 → 保留 `P(类|词) ≥ 0.6`、提升度 `lift ≥ 2`、出现 ≥10 次的词 → 去掉与种子或已选词互为子串的碎片，每类最多 40 个，权重 `0.5 + 0.4·min(1,P)`。

**4. 横批（2~7 字，四字优先）。**
- 候选：所属分类的横批库，加上通用库（有分类时基础分 0.35）。
- 得分 = 分类权重 + 用字重叠加分（每字 0.15，最多计 2 字）+ 意象匹配加分（横批字落在命中词内，每字 0.10，最多计 2 字）；非四字扣 0.05。
- 过滤：横批整句出现在上下联中不选；与上下联重叠字数超过横批字数的一半不选。
- **字数规则**（确定性，见 `derive.length_rules`）：
  - 默认只用四字。
  - **短（2~3 字）**：上下联最长 ≤4 字，且命中词 ≤1 个（意象单一）。
  - **长（5~7 字）**：(a) 四字最佳得分 <0.6 且上下联最长 ≥5 字（四字不贴合）；或 (b) 上下联最长 ≥6 字且有 3 字以上的命中词（长短语）。
  - 允许的字数档里得分最高者胜出，同分按横批字典序。
- **分散**：每个横批的使用数不超过其所属分类首选数的 15%（下限 3）；全部候选超限时取最优并计入“超限次数”，全量运行为 0。

全程无随机数，同一输入每次结果一致（测试覆盖）。

## 输出

- `derived.tsv`：无表头，每行 `上联\t下联\t横批\t分类1:权重,分类2:权重…`，上下联已去空格，权重两位小数。
- `stats.json`：去重数、耗时、回落比例、挽联否决次数、横批字数分布、字数选择原因分布、各类首选数与四字占比、权重直方图、横批 Top20 与占比、各类内单横批最大占比。

## 全量结果（最终版）

- 去重后 736,214 对，耗时约 93 秒（第一遍 13 秒 + 第二遍约 80 秒），`derived.tsv` 约 63MB。
- 回落通用 38.9%；挽联否决触发 17,431 次（约 2.4%）；横批超限 0。
- 字数：四字 99.62%，二字 0.02%，五字 <0.01%，七字 0.36%；字数原因：四字 99.62%、长（四字不贴合）0.32%、长（长短语）0.04%、短（意象单一）0.02%。
- 首选分类占比：山水约 24%、通用约 39%、文墨约 15%、人生约 5%、挽联约 3%，其余各 0.1%~2.3%。
- 每类单横批最大占首选比例 ≤15%（文墨约 8.7%，祝寿约 13.3%）。
- 横批库：584 条，2 字 46、3 字 16、4 字 457、5~7 字 65（5 字 2、6 字 1、7 字 62）；每类四字占比 75%~81%。

## 局限

- **准确率有限。** 抽检 60 条（每类至少 3 条，挽联/通用各 6 条）：严格判断约 57% 合理，含部分合理约 68%。这批样本同时用于调词，结果偏乐观，真实准确率需要人工金标集才能估计。
- **挽联会误判。** 抽检挽联 6 条里只有 1 条明确合理，其余多为“泪”“逝”“祭”一类词造成的非哀悼用法。规则设计上宁可误判也不让挽联进喜庆类，所以误判会偏多；`魂`“灵”等字已降权或从否决中移出。无标注，无法估计挽联的漏判率。
- **词是字串，不是分词。** 挖掘词是 2~4 字子串，仍有碎片（如“声辞”“迎春春”）与单首诗的重复句；黑名单只删了二十多个明显的误判词。
- **通用占比高。** 近四成对联没有任何词命中，只能归通用；单个自然字（雁、鸟、月）达不到阈值，写景联常落通用。
- **横批是启发式。** 横批库是手写的吉利/庄重短语，并非原联的真实横批；四字占比高是规则和分值设计的结果，不代表用户偏好。2~3 字与 5~7 字横批很少被选中（只有少数对联满足字数规则），抽检里一条 7 字横批（“花好月圆人长久”配“鸟出涪陵”的婚庆联）的选择就不太合理，说明长短语规则还较粗。
- **无第三方分词。** 未引入 jieba 等依赖（依赖需先征得同意）。

## 下一步建议

1. 人工标注 200~300 条金标（分类 + 是否可作横批），用它评估并调阈值，而不是拿抽检样本调词。
2. 征得同意后考虑引入分词库（如 jieba），用词而非子串做挖掘，可明显减少碎片。
3. 扩充横批库中的五到七字横批，并给长横批规则加一个“最低匹配度”门槛。
4. 对挽联类做二级确认（例如同时命中两个哀悼词或哀悼词位于句尾），在保留默认排除的前提下降低误判。
