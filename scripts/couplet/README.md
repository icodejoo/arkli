# 对联分类与推荐横批推导（第二版）

给对联训练集（去重后 736,214 对）里的每一副对联推导 **0~3 个分类（带 0~1 权重）** 和 **一条推荐横批**。
横批是推荐值，**不是原联的真实横批**；分类也是推导值，只适合做 App 的粗筛与默认排除。

第一版（提交 2f001d3，已在 90d7d2d 删除）验收不合格，本版推倒重来：先做盲标金标（dev/holdout 分开），再做“词典弱标签 + 统计模型”，最后**只在 holdout 上一次性报告成绩**。**本版在 holdout 上仍有三项没过验收线**，见下文“结果”。

## 怎么跑

全部只用标准库，命令都带 `python -I`。

```powershell
cd scripts/couplet
python -I test_couplet.py                       # 单测（26 个，约 1 秒）
python -I derive.py --limit 30000 --out <临时目录>  # 试跑：只取前 3 万对（训练也只用这些）
python -I derive.py                             # 全量：约 8~12 分钟，写 derived.tsv + stats.json
python -I derive.py --eval both --sheet         # 全量 + 在金标 dev/holdout 上评估，另写横批判定表
python -I derive.py --eval both --eval-only     # 只训练和评估（读人工横批判定），合并进已有 stats.json
```

默认数据 `E:\workspaces\arkli-models\_src\couplet-clean\x\couplets\train`，默认输出 `E:\workspaces\arkli-models\_src\couplet-derived\`：

- `derived.tsv`：无表头，`上联\t下联\t横批\t分类1:权重,分类2:权重…`，去空格、去重后全量，权重两位小数；
- `stats.json`：各类数量与权重分布、横批 Top 与占比分布、字数分布、回落率、挽联判定分布、金标评估结果、参数；
- `banner_sheet_{dev,holdout}.tsv`：横批判定表（供人工逐条判定）。

## 方法

### 分类

1. **词典**：每类按权重分档（3 = 单词即可定类，2 强，1 中，≤0.5 弱）。匹配时每个起点只取最长词条，并丢弃被前面更长词条覆盖的命中；配合 `_中性` 组（如“千古风流”“奠基”“力挽”“灵秀”）消歧。单字只放弱档，避免第一版“单字意象 0.4 就能过阈值”的问题。两联都命中同类时乘 1.25。
2. **弱标签**：词典首选分 ≥3 且 ≥ 次选分 × 1.5 的对联打上该类标签（约 32 万对有标签）。
3. **朴素贝叶斯**：特征为单字和分句内二元组（全库频次 ≥20），在全库上统计背景频率、在弱标签对联上统计类频率，向背景收缩（伪文档 50），单特征对数提升度截断在 ±3。每副对联输出两种聚合：
   - 收缩均值 = Σ提升度 /（特征数 + 6），看整体主题，短联自动向 0 收缩；
   - top-5 均值 = 最强 5 个特征的平均，看“有没有几个强线索”，用于挽联检测。
4. **融合**：每类综合分 z = 词典分 + 16 × 收缩均值；权重 w = 1 − exp(−z/1.5)。首选权重 < 0.3 则回落“通用”；次选须 w ≥ 0.6 且 z ≥ 首个主题类 z × 0.4；最多 3 类。
5. **挽联两级判定**（召回优先）：挽联分 = min(挽联词典分, 2) + 2 × 挽联 top-5 提升度。
   - 强判定（命中单个权重 3 的挽联词，或挽联分 ≥ 6.5）：挽联置首；
   - 弱判定（挽联分 ≥ 4.5）：挽联作为附加标签排在主题类之后（App 照样能据“含挽联”隐藏）；
   - 两种判定都会去掉春节/节庆/婚庆/祝寿/乔迁/开业这些喜庆类。
6. 试过但没用的：自训练（用第一轮高置信结果再训一轮，dev 降 2 个点）、同上联/同下联分组证据（征对的对句题材分散，越加越差）、大类偏置（两折交叉验证不泛化）。参数都在 dev 上定，见 `classify.PARAMS`。

### 横批

1. **横批库** `banners.json`：按“类 → 场景节点”组织（如 山水-秋景、怀古-禅佛、挽联-英烈），每个节点有触发词（可写“词:权重”、`min_hits`、`need_sad`）、基调（喜/雅/感/庄/励/讽）、四字主表 `b4`、二三字 `b2`、五至七字 `bl`。共 123 个节点、1980 条不重复横批（条目计四字 1929、二三字 239、五至七字 52）。
2. **选节点**：候选为预测分类下的节点，节点分 = 类权重 × 2 + 触发词命中分（单字 0.8、多字 1.2，封顶 3；无触发词的通用节点给 0.7）；取与最高分相差 0.3 以内的节点合并为候选池。
   - 挽联居首或强判定：只用挽联节点；
   - 挽联弱判定：不用挽联横批、不用喜庆/励志基调；对联带感伤线索时再收紧到庄重/感怀，并让“通用-感怀”节点参与竞争；
   - 首选权重 < 0.9：让“通用-妙对”评点式横批参与竞争；回落“通用”时参考统计模型的最佳猜测类；
   - 感伤对联（命中 ≥2 个感伤字词）：排除喜庆/励志基调，感怀节点加分。
3. **过滤**：不得是上下联的原句片段；与对联重合的字过半即弃；季节相反即弃（秋联不配“春暖花开”）；**意象落地**——横批里的具体意象字（山、江、舟、雪、松、雁、琴、棋……）至少一半要在对联里出现或与对联用字强关联（PMI ≥ 2.5），否则不选。
4. **加权抽取**：候选权重 = exp(0.6 × 意象关联分)，关联分来自全库同联共现 PMI；再用 md5(上联|下联) 做确定性加权抽取。**同一副对联每次结果相同，不依赖全库计数或处理顺序**；分散度靠节点和候选数保证。
5. **字数**：每联最长 ≤3 字的短联优先 2~3 字横批；每联 ≥16 字的长联按哈希约 35% 取 5~7 字（长横批只保留概括性的，如“江山如此多娇”“音容笑貌永存”）；其余一律四字。全库四字 95.8%、二三字 2.4%、五至七字 1.8%：真实横批绝大多数是四字，短联配短横批、长联偶尔配长横批，比例与语料的长度分布（≤3 字联 2.4%、≥16 字联 11.7%）对得上。
6. 试过但没用的：横批“语境画像”（收集含该成语的对联用字，按相似度加权；减去自身基线后在 dev 上净效果约为 0，已撤掉）、只取最高分节点并加大关联权重（dev 更差）。

## 金标与评估

- **抽样**（`gold_sample.py`，种子固定）：412 条分层盲标——纯随机 140、v0 词典挽联强命中 50、挽联弱线索 40、14 个主题类各 12、词典无命中 14；每层交替分入 dev/holdout。标注时打乱顺序、只看文本，不看分层。
- **挽联补抽**：上面 412 条里真挽联只有 11 条，于是另抽 3600 条纯随机对联逐条通读，挑出挽联“是”45 条、“疑”25 条并入金标；这 3600 条的挽联标记全部保存在 `gold/wan_pool.tsv`，因此挽联召回和精确率可以在纯随机样本上**无偏**估计。挽联“是”共 56 条（dev 24 / holdout 32）。
- **标注内容**：每条写可接受的分类集合（首个为最佳）、挽联 是/疑/否、横批应贴合的主题与忌讳基调。**全部由模型（Claude）标注，不是人工专家标注。**
- **口径**：首选合理 = 首选类在可接受集合内；任一合理 = 至少一个输出类在集合内；挽联召回按“输出里含挽联”算（强弱判定都算）。
- **纪律**：所有词典、参数、横批库调整都只看 dev；holdout 只在最后跑了一次，之后没有再改任何东西。
- **横批判定标准**（事先定好）：横批能概括或呼应对联主题/场景/情绪中的至少一个主要方面，读来不突兀；不与基调相反、不与季节或对象冲突、不照搬原句；主题不明的泛联，评点式或与字面意象相合的横批算合格。

### 全库

- 736,214 对，训练约 50 秒，推导约 7~10 分钟（全程约 8~12 分钟）；训练+评估阶段实测峰值内存 625MB；`derived.tsv` 约 61MB（64,453,031 字节）。
- 首选：山水 26.4%、人生 12.7%、家国 12.7%、怀古 12.4%、文墨 10.2%、情感 6.5%、春节 4.0%、事业 3.1%、通用 3.0%、学业 2.7%、挽联 2.1%、开业 1.7%、祝寿/节庆 各 0.9%、婚庆 0.7%、乔迁 0.2%。

- 横批：用到 1954 条不同横批；最大单条“往事悠悠”0.58%（它同时出现在情感、怀古、通用-感怀多个节点里），没有超过 1% 的；占比 0.5%~1% 的 1 条、0.1%~0.5% 的 304 条，其余都低于 0.1%；四字 95.8%。

## 局限与系统性错误

1. **分类停在 82% 左右**。主要混淆在大类之间：怀古成了“文言风格联”的兜底（文绉绉但不咏史的联被判怀古），山水/人生/情感互相串，事业与家国（“追梦兴邦”）分不清。词典 + 朴素贝叶斯只能看字面，dev 与 holdout 差 3 个点说明词典有一部分是对着 dev 补的。
2. **挽联召回 90.6%**：靠词典强词 + 统计线索能抓住有“悼、噩耗、音容、九泉、驾鹤”等字面的；靠典故、语气表达哀思的（“胡不寿”“蓼莪”“贞元朝士更无人”）只能靠补词，补不全。为了召回，误报控制在约 3.4%（被误隐藏的多是咏史、英烈纪念、伤感抒情联）。
3. **横批只有 57%**：约一半失败来自分类本身错了，另一半是同一节点里的候选“意思对不上”（节点只表达“类+场景”，表达不了“这副联具体在说什么”）。字面共现、成语语境画像都试过，提升不明显。
4. 金标、横批判定都是模型自己做的，有主观性；holdout 247 条，单项指标的误差约 ±3~5 个点。

## 要达标还需要什么（需要你拍板）

- **分类**：要么人工标注 2000~3000 条训练集（不是金标），换成有监督分类（标准库可实现逻辑回归）；要么引入外部资源——分词/成语词典（如 jieba + 成语库）用于特征，或用大模型离线批量打标签再蒸馏。按经验前者能把首选推到 85% 以上，但不保证。
- **挽联**：如果“宁可多判”优先，可以把门槛从 4.5 降到 3.5（holdout 召回 31/32，误隐藏升到约 9%）；要同时压误报，需要更多真实挽联样本做有监督训练。
- **横批**：模板库 + 规则匹配的上限大概就在 60%~70%。要到 80%，比较现实的路是让横批生成具备“读懂这副联”的能力：用大模型离线为全库生成或挑选横批（再用本库做格式与分散度约束），或者至少为大类训练一个“对联 → 横批”的匹配模型（需要成对标注）。这两条都超出“只用标准库”的范围，需要你同意后再做。
